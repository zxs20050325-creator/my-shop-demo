# 冀遗筑梦部署与运维手册

## 1. 部署前检查

1. 六个迁移脚本已按顺序在 Supabase 执行。
2. `backend/scripts/verify-migrations.js` 检查通过。
3. 管理员账号已使用 `create-admin.js` 创建。
4. `JWT_SECRET` 是至少 32 位随机字符串。
5. `render.yaml` 中不含任何数据库密码或 JWT 密钥。

本地可通过 `DATABASE_URL` 自动执行迁移：

```powershell
npm run migrate --prefix backend
```

## 2. Render 环境变量

```text
NODE_VERSION=24.11.0
NODE_ENV=production
DATABASE_URL=postgresql://postgres.项目引用:密码@连接池域名:5432/postgres
JWT_SECRET=随机长密钥
COOKIE_SECURE=true
CORS_ORIGIN=https://你的正式域名
```

`DATABASE_URL`、`JWT_SECRET` 和 `CORS_ORIGIN` 推荐设置为 Render Secret，不要提交进 Git。

## 3. Render 配置

`render.yaml` 已配置：

- 根目录：`backend`
- 构建：安装后端和生产依赖、构建前端、检查 `frontend/dist/index.html`
- 启动：`npm start`
- 健康检查：`/health`

## 4. 上线验证

1. 打开 `/health`，确认返回 `success: true`。
2. 注册普通用户并登录。
3. 打开商品详情，选择规格并加入购物车。
4. 添加收货地址，创建订单并完成演示支付。
5. 在订单详情中申请退款。
6. 使用管理员账号登录后台，同意退款。
7. 检查库存恢复、订单状态和 KPI。
8. 清理行为日志，确认成交订单数和营收不归零。

## 5. 备份与恢复

- Supabase 开启自动备份。
- 每次执行迁移前导出一份数据库备份。
- 部署前使用 `git status` 检查未提交文件。
- 回滚应用代码不会自动回滚数据库，生产迁移必须先在测试 Supabase 验证。

## 6. 常见问题

### 登录后马上退回到登录页

- 检查浏览器是否阻止 Cookie。
- 生产环境确认使用 HTTPS，`COOKIE_SECURE=true`。
- 检查 `CORS_ORIGIN` 是否与浏览器地址完全一致。

### 提交写请求返回 403

- 检查 `Origin` 是否在 `CORS_ORIGIN` 白名单中。
- 检查 Vite 代理地址或 Render 自定义域名。

### 下单提示库存不足

- 后台检查对应 SKU 库存。
- 检查购物车数量是否大于库存。
- 并发订单会通过数据库行锁保证库存不会被超卖。

### 管理员登录成功但看不到后台

- 确认该用户在 `users` 表中的 `role` 是 `admin`。
- 使用 `create-admin.js` 再次更新该账号角色。
