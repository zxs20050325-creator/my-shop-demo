# 冀遗筑梦答辩专用文稿

## 一、项目定位

冀遗筑梦是一个以河北古建筑和非遗文化为主题的数字化盲盒电商平台。项目保留盲盒翻牌展示特色，但没有引入复杂概率和稀有度系统，重点展示完整电商闭环、工程分层和安全性改造。

## 二、本次重构解决的问题

重构前系统存在三类问题：

1. 用户身份只在浏览器本地保存用户名，后端信任前端参数，存在身份伪造和订单越权风险。
2. 下单、清购物车和日志写入不在同一事务，可能导致重复订单和数据不一致。
3. 商品缺少 SKU、库存、退款和完整状态流转，不能形成标准电商闭环。

## 三、整体架构

前端使用 Vue 3、Pinia 和 Vue Router。所有请求通过统一 API 客户端进入 Express。

后端采用模块化分层：

```text
路由 -> 参数校验 -> 业务服务 -> 仓库层 -> Supabase RPC
```

数据库负责订单、库存和退款等必须保证原子性的操作。

## 四、安全改造

### JWT 鉴权

- Access Token 放在 HttpOnly Cookie，前端脚本无法读取。
- Refresh Token 在数据库只保存哈希。
- SQL 查询使用 `req.user.id`，不再接收请求体中的用户名。
- 订单详情、取消、支付和退款接口都会验证订单归属。

### 管理员安全

- 管理员是数据库中的 `users.role = admin`。
- 管理员密码使用 scrypt 哈希。
- 删除 Render 中的硬编码口令。
- 后台接口不返回密码哈希。

### 其他安全措施

- 登录和注册限流。
- Zod 参数校验。
- Helmet 安全响应头。
- Origin 校验。
- 统一异常和响应格式。

## 五、完整电商业务

### SKU 与库存

每个商品至少拥有一个 SKU。不同规格拥有独立价格、库存和上下架状态。

### 原子下单

`create_order_from_cart` 在同一个事务内完成：

1. 锁定购物车和 SKU。
2. 校验商品状态、实时价格和库存。
3. 创建订单和订单明细。
4. 扣减库存并写库存流水。
5. 清空购物车。
6. 写订单状态日志和用户行为日志。

任何一步失败都会整体回滚。

### 订单状态

订单状态为：

```text
待付款 -> 待发货 -> 已发货 -> 已完成
待付款 -> 已取消
```

演示支付完成待付款到待发货的流转。

### 退款

已付款且未完成的订单可以申请退款。管理员能够同意或拒绝，同意后退款状态、订单状态和库存会在事务中同步处理。

### 用户中心

支持资料修改、密码修改、多收货地址和默认地址。

## 六、KPI 数据口径

重构后：

- 成交额和订单数来自订单表。
- 热门商品来自已付款订单明细。
- 行为日志只用于页面流量和行为分析。

因此清空行为日志不会导致订单 KPI 归零，也不会把搜索关键词计入热门商品。

## 七、演示流程

1. 注册普通用户并登录。
2. 打开商品详情，切换不同规格，观察价格和库存变化。
3. 加入购物车并创建订单。
4. 使用演示支付，订单变为待发货。
5. 申请退款。
6. 使用管理员账号进入后台。
7. 查看 KPI、趋势、商品和订单。
8. 同意退款并验证库存与状态。
9. 清空行为日志，展示交易 KPI 保持不变。

## 八、创新点

1. 保留非遗盲盒翻牌特色，同时补齐标准电商能力。
2. 使用 Supabase RPC 将库存和订单放在同一事务中。
3. 将前端视觉与业务分层解耦，可继续扩展优惠券、物流和评价。
4. 将安全改造和业务重构同时落地，适合软著申报和答辩展示。
